# Gaiaball v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy Gaiaball firmware with a modular FreeRTOS/NimBLE firmware (binary BLE protocol, runtime configuration, robust IMU pipeline), plus a standalone Web Bluetooth config app with 3D visualization, a minimal binary decoder in Gaiasenses-web, and an interactive HTML report (pt-BR).

**Architecture:** Firmware splits pure logic (`src/logic/`, host-testable with PlatformIO native+Unity) from ESP32 services (`src/services/`, FreeRTOS tasks: acquisition on core 1, BLE on core 0, queues between). The wire protocol is packed little-endian structs shared as golden byte vectors between firmware tests, config-app tests (vitest) and Gaiasenses-web tests (node:test). The site keeps its whole smoothing/Pd pipeline: only the BLE decode layer changes.

**Tech Stack:** ESP32 Arduino core 2.0.17 (PlatformIO `espressif32@6.12.0`), NimBLE-Arduino 1.4.3, vendored SparkFun ICM_20948 (DMP enabled), Unity tests; Vite + TypeScript + three.js + vitest (config-app); Next.js + node:test (Gaiasenses-web).

**Spec:** `docs/superpowers/specs/2026-11-06-gaiaball-v2-design.md` (approved design; read it first — it carries the legacy-firmware diagnosis and all user decisions).

## Global Constraints

- Never modify `firmware-original.ino` or `relatorio.md`.
- Repos/branches: gaiaball repo → work on branch `feature/firmware-v2` (create from `main`). Gaiasenses-web repo (`/home/nyck/cti/Gaiasenses-web`) → branch `feature/gaiaball-binary-protocol` (create from `main`; Task 17 only).
- Code + comments in technical English. Config-app UI and HTML report in pt-BR.
- BLE UUIDs fixed: service `19b10000-e8f2-537e-4f6c-d104768a1214`; characteristics `…0001` (IMU notify), `…0002` (command write), `…0003` (CO₂ notify), `…0004` (config TLV read/write), `…0005` (diagnostics notify).
- Wire format: little-endian, `__attribute__((packed))`, protocol version `1`, quaternion scale **int16 × 1/16384**, accel raw DMP counts (int16 passthrough).
- Firmware hot paths: no Arduino `String`, no per-sample heap allocation, no `ArduinoJson`.
- PIN register (TLV `0x41`) is write-only: redact it from every config read/dump.
- Default config values = legacy behavior values (see Task 4 table) so the installation behaves the same before tuning.
- Euler convention everywhere = legacy remap: `qw=w, qx=y, qy=x, qz=-z` then standard roll/pitch/yaw (matches `firmware-original.ino` L558-574); it lives only in decoders/tests, never on the wire.
- Gaiasenses-web: after code changes run `graphify update .` (project CLAUDE.md rule).
- Commits: conventional messages (`feat:`, `test:`, `docs:`); commit at the end of every task.

## Review Focus

Failure modes the spec implies; each line's test is pinned to the owning task:

1. Garbage/truncated BLE notification at the site decoder must return `null`, never throw (legacy site lost samples to uncaught `JSON.parse`/TypeError) → Task 17 tests.
2. CO₂ byte stream desync (header byte `0x42` appearing inside a frame payload, partial frames) must resync to the next real frame instead of discarding forever → Task 5 tests.
3. DMP quaternion with `q1²+q2²+q3²  > 1` or NaN must be sanitized/flagged; a NaN must never be encoded onto the wire (this is the "globo alucina" bug) → Task 3 + Task 2 tests.
4. `seq` wraparound (65535→0) must not report a huge packet-loss spike in the config-app metrics → Task 13 tests.
5. A TLV write with unknown id, wrong length, or truncated buffer must change nothing (no partial apply) → Task 4 tests.
